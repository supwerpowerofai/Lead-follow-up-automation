# SUPERPOWER AI — Repository Standard

> Build practical AI capabilities people can try, inspect, and trust.

SUPERPOWER AI is a growing universe of practical AI tools. Each repository should combine memorable positioning with credible engineering: a clear problem, a useful solution, reproducible proof, and an honest next step.

## The seven-stage structure

### 1. Hook — earn curiosity
Open with one specific, outcome-oriented sentence. Avoid vague claims such as “revolutionary AI” or “the future is here.”

**Example:** “Turn missed leads into a follow-up workflow you can inspect and improve.”

### 2. Problem — make the friction recognizable
Explain who experiences the problem, what is frustrating or expensive about it, and why it matters. Use numbers only when they are sourced or measured.

### 3. Promise — state the practical outcome
Describe what the software actually does and who it helps. Clearly distinguish working features from planned features.

### 4. Proof — demonstrate, don't exaggerate
Use a working demo, screenshots, reproducible sample output, automated tests, architecture notes, or measured benchmarks where appropriate. Never invent users, testimonials, performance results, or revenue.

### 5. Quick win — make the first try easy
Provide prerequisites, installation steps, safe sample data, a short example command, and expected output. Prefer a useful demo that can be tried without paid services when feasible.

### 6. Upgrade path — offer a relevant next step
Link to real documentation, advanced features, integrations, templates, implementation services, or paid products only when they genuinely exist and are ready to be offered.

### 7. Real urgency — never manufacture scarcity
Use genuine beta windows, actual release milestones, or truly limited support capacity. If there is no real deadline, provide a clear next action instead of fake countdowns or false scarcity.

## Recommended README order

1. Project name and one-sentence hook
2. Project status and relevant links
3. Problem and intended users
4. What works today
5. Demo, screenshots, sample input/output
6. Quick start and prerequisites
7. How it works and architecture
8. Tests, evidence, limitations, and security notes
9. Roadmap and contribution instructions
10. License and a real next step

## Release checklist

- [ ] The hook names a specific benefit.
- [ ] The intended user and problem are clear.
- [ ] Claims match implemented behavior.
- [ ] A demo, sample output, or reproducible test is included.
- [ ] Setup instructions have been tested.
- [ ] Secrets and private data are protected.
- [ ] Limitations and current status are disclosed.
- [ ] Links, contact details, and upgrade offers are real.
- [ ] Any deadline or scarcity claim is genuine.
- [ ] Dependencies and licensing have been reviewed.

## Flagship sequence

1. **powerof-ai** — the SUPERPOWER AI front door and practical AI showcase.
2. **leadstorm-ai** — a lead follow-up and pipeline automation demonstration.
3. **agent-nexus** — a modular AI agent workflow with explicit tool permissions, logs, error handling, and tests.

Names and scope are planning choices until each project is implemented and validated. A project must not be described as production-ready merely because its README is polished.

## Core principle

**Make the promise compelling. Make the proof real. Make the next step obvious.**

The objective is not repository count alone. It is a portfolio of useful, maintainable projects that demonstrates the ability to solve real problems.
